# Ролевая модель доступа к Kubernetes — PropDevelopment

## Контекст

Большинство бизнес-сервисов PropDevelopment разворачиваются в Kubernetes. Доменная организация компании (Продажи, ЖКУ, Финансы, Дата) проецируется на namespace'ы кластера: `domain-sales`, `domain-zhku`, `domain-finance`, `domain-data`. Аутентификация — по клиентским x509-сертификатам, подписанным CA Minikube; группа Kubernetes кодируется через поле `O=` в Subject сертификата.

## Таблица ролей

| Роль | Права роли | Группы пользователей |
| --- | --- | --- |
| `cluster-admin` *(built-in)* | Полный контроль кластера: все ресурсы во всех namespace, все verbs (включая `secrets`, RBAC, ноды, CRD, политики). | `cluster-admins` — платформенная команда (DevOps Lead, SRE) |
| `security-auditor` *(custom, привилегированная)* | Read-only по всему кластеру **с доступом к `secrets`**, RBAC-объектам, NetworkPolicy и audit events. Без права на изменения. Нужна для расследований инцидентов и проверок compliance. | `security` — специалист по информационной безопасности |
| `cluster-viewer` *(custom)* | Read-only по pods, services, deployments, statefulsets, daemonsets, ingress, configmaps, namespaces, PV/PVC, jobs/cronjobs, nodes. **Без доступа к `secrets`** и без RBAC-объектов. | `cluster-viewers` — бизнес-аналитики, продуктовые менеджеры (наблюдение за состоянием кластера без чувствительных данных) |
| `cluster-configurator` *(custom)* | CRUD cluster-level настроек: `Ingress`, `IngressClass`, `NetworkPolicy`, `ResourceQuota`, `LimitRange`, `StorageClass`, `PriorityClass`, `Namespace`. Read-only по workloads. **Без `secrets` и без RBAC** (иначе была бы возможность само-эскалации). | `cluster-configurators` — Platform Engineers (junior уровень платформенной команды; настраивают платформу без RBAC и `secrets`). Доменные DevOps сюда **не входят** — кластерные настройки кросс-доменные и не должны быть в руках одного домена |
| `domain-developer` *(custom, namespace-scoped)* | CRUD в namespace своего домена: pods, deployments, statefulsets, services, configmaps, ingress, jobs/cronjobs, PVC. Read-only по RBAC своего namespace. **Без чтения `secrets`** (секреты можно использовать в манифестах через `envFrom`/`volumeMount` без чтения значений через `kubectl`). | `sales-developers`, `zhku-developers`, `finance-developers`, `data-developers` — разработчики продуктовых команд соответствующих доменов |

## Сводка по требованиям задания

| Требование | Реализация |
| --- | --- |
| Привилегированные группы (например, просмотр секретов) | `cluster-admins` (полный доступ) и `security` (read-only including secrets) |
| Группа только для просмотра ресурсов кластера | `cluster-viewers` (read-only без secrets и RBAC) |
| Группа для настройки кластера | `cluster-configurators` (cluster-level настройки без secrets и RBAC) |
| Разграничение по орг. структуре | 4 группы `*-developers`, каждая привязана к своему namespace через `RoleBinding` |
