# Проверочный лист по информационной безопасности — PropDevelopment

## 1. Выбор разделов и обоснование

Аудит безопасности заявлен компанией как **комплексный** — он одновременно решает четыре потребности (повышение удовлетворённости клиентов, разблокировка data-сервисов, реакция на инциденты, проверка compliance с законодательством РФ), а корневые проблемы (нарушенный контроль данных и небезопасные API партнёров) затрагивают весь стек: от прав доступа до физической инфраструктуры. Сужать охват в этой ситуации — значит пропускать релевантные риски.

**Включены все шесть разделов шаблона**, но с разным приоритетом и глубиной проработки:

| Раздел | Приоритет | Почему включён именно для PropDevelopment |
|---|---|---|
| **I. Управление доступом** | Критический | Корневая проблема: API партнёров-УК позволяют видеть и менять данные клиентов чужих ЖК; жалобы клиентов на отображение чужих ПДн в личном кабинете. `auth-service-1` — централизованная единая точка, её компрометация даёт полный доступ ко всем системам. |
| **II. Безопасность данных** | Критический | Заявлена самой компанией как ключевая проблема («нарушен контроль данных»). Compliance с ФЗ-152 — обязательное условие развития BI/ML/AI-сервисов. Резервные копии всех БД упомянуты, но защищённость их хранения не подтверждена. |
| **III. Защита инфраструктуры** | Высокий | Гибридная инфраструктура (свой ЦОД + приватное облако + арендованные мощности облачного провайдера) расширяет периметр. В описании системы упомянут только firewall — нужно проверить наличие сегментации, IDS/IPS, сканирования уязвимостей. |
| **IV. Управление инцидентами** | Высокий | Прямой драйвер аудита — «отреагировать на инциденты и рыночные изменения» после утечки у конкурента. Усугубляющий фактор: один ИБ-специалист на всю компанию + нарушенный процесс передачи ему решений из IT-команд → высокий риск необнаруженных инцидентов. |
| **V.1. Мобильные устройства, удалённый доступ, облако** | Средний | Распределённые продуктовые команды требуют удалённого доступа; арендованное облако делает облачные политики бэкапов и контроля доступа релевантными. |
| **V.2. Оборудование и физическая безопасность** | Средний | У компании есть свой ЦОД — физический доступ к серверным и инвентаризация активов релевантны. В кейсе данных по физ.периметру мало, поэтому раздел сокращён до базовых вопросов. |


## 2. Условные обозначения

- **Да** — практика подтверждена описанием системы или C4-диаграммой.
- **Нет** — практика прямо противоречит описанной проблеме.
- **Частично** — реализована не полностью или не на всех системах.
- **?** — данных в кейсе недостаточно, требуется проверка у IT/ИБ-команд PropDevelopment.
